# Morph Gen-1 Package Foundation v1

## Canonical hardening generation 1.15.0

- GitHub is the implementation source of truth. Founder recessives remain
  Ember/PLASMA, Breeze/LIGHT, Sentinel/METAL, and Pulse/SOUND.
- All six unordered public two-primitive combinations are admitted:
  PLASMA, MAGMA, STEAM, DUST, STORM, and VERDURE.
- Every package carries a verified canonical `content_digest`.
- Evolution presentation references must resolve inside the admitted package
  set; the built-ins bind `PRES-GEN1-CANONICAL`.
- Element/form IDs are registry-driven, so a future Founder requires one new
  element registration rather than resolver logic changes.
- Source-package admission is no-effect. Any persisted Morph transition also
  requires the exact WHO/WHAT/WHEN/WHERE/HOW, authority, predecessor, rollback,
  and receipt envelope.
- Environmental context may select or unlock a reversible CONTEXT form; it
  never raises permanent elemental mastery or rewrites lineage by itself.

Gen-1 freezes an extensible grammar, not a fixed catalog of final bodies. Morph identity and life remain canonical while Founder, Evolution, and Presentation packages add admitted possibilities.

## Stable registry

Element IDs are append-only: 01 FIRE, 02 AIR, 03 EARTH, 04 WATER. F-nn, E-nn, and L1-nn are different origin classes over the same elemental lineage. L2-aa.bb records a sorted Founder-descendant elemental vector. Names, localization, ownership, and frames never change these IDs.

## Founder Package

A Founder package registers one new element and binds its F, E, and L1 IDs, primary and recessive affinities, unique origin signature, palette, word pools, catalysts, fallback, compatibility, digest, and fixtures. Installing a public package never grants private Founder identity.

## Evolution Package

Evolution is a graph of permanently unlocked possible forms, not a ladder. Gen-1 activates NATURAL, CONTEXT, RESONANCE, and CULMINATION forms. FRAME_ARMOR, COMBINED, and BATTLE are reserved extension classes and fail closed until separately admitted.

Eligibility resolves from immutable lineage plus bounded 0..5 evidence for CARE, RELATIONSHIP, WEATHER, LOCATION, FRAME, ACTIVITY, CAPABILITY, EVENT, and ENERGY, together with a present registered catalyst. Expression is not evolution evidence.

A manifested form may safely return to a resting form when context or energy changes. Reversion never erases an unlocked form, mastery, lineage, or Chronicle history. Low expression never punishes a Morph with devolution. Forced or anomalous forms remain a future package class.

## Presentation Package

A Presentation package maps canonical form IDs to silhouettes, palettes, effects, animation, voice, localization, accessibility, and frame capability profiles. It cannot write DNA, lineage, care, life, relationships, evolution eligibility, mastery, or authority. Unsupported hardware uses SEREIN-CANONICAL-FALLBACK with the SERN-LOW profile.

## Morph Engine core ownership

- Platform loads packages and evaluates runtime/frame compatibility.
- Root owns immutable identity, origin, lineage, generation, and parentage.
- Memory owns absorbed evidence, unlocks, mastery, and Chronicle.
- Knowledge resolves compatible branches and catalysts.
- UI renders admitted visual presentation.
- Audio renders admitted voice and call presentation.
- Personality selects current expression from care, relationship, and context.
- Modular admits package schemas, versions, dependencies, and digests.
- Cloud carries package references and portable truth while preserving one active owner.

No package may write across a Core boundary without an admitted adapter.

## Resolution

MORPH IDENTITY + ADMITTED PACKAGES + ACCUMULATED EVIDENCE + PRESENT CATALYST + FRAME CAPABILITIES = ELIGIBLE AND MANIFESTABLE FORMS

Different lineages may converge on a compatible form. One lineage may branch into many forms. Gen-2 inherits affinities and possible routes rather than copying a parent's completed body.

## Version and safety law

Package envelopes use serein.morph-package.v1, an immutable package ID with semantic version, engine-major compatibility, fallback, and executable fixtures. Unknown IDs, incompatible majors, duplicate packages, unregistered elements, missing fallbacks, inactive evolution classes, and presentation attempts to mutate Morph truth fail closed with no Morph effect.

## Gen-1 acceptance

The golden suite proves four shared elemental lineages and Founder prefixes, drop-in registration of a fifth element/Founder without resolver changes, branching eligibility, expression/evolution separation, safe reversion semantics, drop-in presentation and constrained fallback, reserved future classes, deterministic digests, and duplicate or invalid package rejection.

The built-in registry supplies four Founder packages and sixteen elemental evolution packages: one NATURAL, CONTEXT, RESONANCE, and CULMINATION branch for each primitive element. These are machine-stable branch seeds, not a closed catalog of player-facing bodies. The cross-platform fixture proves identical eligible-form truth with different SERN-LOW and Android presentation profiles.
